## F-3 v3：低内存档（分块分包）

> 未排期；口径待拍。定位：**v1 = 速度，v2 = 安全性，v3 = 极低内存 + 分块分包**。

**目标**：常驻内存压到"目录 + 当前索引段 + 当前数据块"，编码与解码全程流式；去掉现在三个峰值——整树 `fsys_`、整块索引、整块数据缓冲。

**分块分包**：数据块取小（64 KiB–1 MiB 级）压低缓冲，数据侧按"包"（若干块 + 包级记录）组织，避免小块把索引记录数顶爆；索引按有序 key 区间分段（SSTable 式），每段自包含；外层目录存"每段首 key / 偏移 / 条目数"，段数过多时目录再分层。

**安全**：沿用 v2 的 AEAD 口径；每段/每包独立 nonce（`kind` 区分 index-group / data-package，`offset` 递增），目录与段/包的尺寸、偏移进 AAD，防跨归档/跨偏移拼接。代价：每段/包多 16 B tag + 尺寸记录，压缩比略降。

**约束**：一个文件的块记录不跨段（单个超大文件允许段溢出）；`get` = 二分段 → 载入该段 → 段内 `select`；`save("*")` 顺序扫段。

**待拍**：① 分组单位（建议有序 key 区间）；② 文件是否允许跨段；③ 数据"包"的粒度（每包块数/字节）；④ 解码 API——`fsystem()` 整树物化与极低内存冲突，需要流式接口或懒视图（API 变更）。

**触发**：仅在超过阈值（文件数或索引大小）时启用；小归档保持单索引。实现细节（编码端边遍历边写段、LZ4 链是否跨段）留到实现时定。
